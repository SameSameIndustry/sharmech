# フィールド寸法 (確定値)

**2026-08-30、ユーザーの手描きスケッチの実測から確定した、赤・青両フィールドの寸法一式。**
**ワーク初期配置の X は 2026-09-12 にフィールド CAD の見直しで 40mm 奥へ訂正した(1行目 270 → 310mm。下記「通常ワーク・共通ワーク」の注記)。**
`catchrobo` プロジェクト全体(このリポジトリ + `catchrobo_webxr_controller` +
`catchrobo_sim_threejs`)で参照する座標の正本はここに置く。各リポジトリの
config/定数コメントはここへのリンクを持ち、値そのものは各リポジトリに複製する
(ROS2 のパラメータやブラウザ側の定数は仕組み上「1箇所を読みに行く」ができないため。
`CLAUDE.md` の「他リポジトリとの整合性確認」と同じ、意図した重複)。

**このページだけで完結するように書いてある。** 元になった手描きスケッチや、確認に
使った作業用の図(artifact)を参照しなくても、この表と図だけで同じ数値を再現できる。

## 座標系

**原点 = ロボット設置エリア(縦300×横700mm)の中心。** `field` 座標系はロボットの
ベース座標系そのもの (`CLAUDE.md`)。ROS REP-103 に沿う。

| 軸 | 向き |
|---|---|
| +X | ロボット設置エリアから作業エリア(通常/共通ワーク側)へ向かう方向。「奥」に相当 |
| +Y | 右から左。ロボット設置エリアに向かって立ち、+X方向(作業エリア側)を見たときの左手方向 |
| Z | 未確定(下記「未確定/今後の課題」) |

## 通常ワーク・共通ワーク (オブジェクト初期配置、24個)

直径71mm(半径35.5mm・CAD実測)・長さ142mmの円柱を、長軸が+X方向を向くように横倒しで
配置。厚さ2.3mmの土台の上に乗る(土台上面の絶対Zは未較正)。**赤・青とも同じ値**
(下記「赤/青の関係」参照)。

> **ワーク直径について (2026-09-05 整理)。** 2026-08-30 のスケッチ実測時には
> 直径66mmと示されたが、`CLAUDE.md` の方針に従い **CAD実測 (半径35.5mm) を正本**とし、
> 66mm は保留の代替候補として扱う。`catchrobo_webxr_controller` の `REAL_FIELD.width`
> (1.071) と `CYLINDER.radius` (0.0355) も同日 35.5mm 基準に統一済み。
> どちらが物理的に正しいかは未確認 (`CLAUDE.md`「既知の未解決の食い違い」参照)。

- 3行(+X方向、ロボットに近い順) × 6列(+Y方向、左から) = 18個が通常ワーク(自陣のみ)
- 最も奥の1行(X=0.910、6個)が共通ワーク(赤・青共通、取り合いになる)
- 行間ピッチ 200mm(+X方向)・列間ピッチ 200mm(+Y方向、列1が最も+Y側=左寄り)

> **X の訂正 (2026-09-12)。** フィールド CAD を見直したところ、原点(ロボット設置エリア中心)から
> 1行目(検出3 = 行1・列3)の中心までは **310mm** で、2026-08-30 のスケッチ実測 270mm より
> 40mm 奥だった(ユーザー確認)。行間・列間ピッチ 200mm は X/Y とも CAD と一致していたので、
> 4行すべてを 40mm 奥へ平行移動した(0.270/0.470/0.670/0.870 → 0.310/0.510/0.710/0.910)。
> Y は変更なし。`robot_geometry.yaml` の `work_placement.first_x_m` / `common_x_m` と、
> それに追従する `workspace.x_max_m`(0.941 → 0.981)を同日に更新済み。
> なおシミュレータ `catchrobo_sim_threejs/src/scene/FieldLoader.js` は CAD 原点を
> 「CAD x=825mm = 設置エリア中心」と置いて旧値 0.270 に合わせていた(コメント参照)ので、
> 今回の読み取りとは 40mm 食い違う。どちらの読み取りが正しいかは CAD で再確認が要る。

## シューティングボックス (オブジェクト設置位置、4箱×6スロット=24箇所)

**2026-09-05: この節はフィールドCAD (`234_2026年度フィールド.step`) の実測に差し替えた。**
それ以前は手描きスケッチ由来で「1箱 255(Y)×510(X)mm、4箱でX方向2040mm」としていたが、
CADの実物とは大きく異なっていた。ルールブック第16回 p.6 に
**「寸法については3DCADデータをもとにし」**と明記されているため、CADを正とする。

### 箱そのもの (ハードウェア)

| 項目 | 値 |
|---|---|
| 外形 | 148mm(X) × 265mm(Y) × 高さ150mm |
| 板厚 | 5mm (底板・側壁とも) |
| 内寸 | 138mm(X) × 255mm(Y) × 深さ145mm |
| 個数 | 各チーム4個 (ルールブック V-3) |

深さ145mmはワークの142mmをわずかに上回るだけで、ボーナス条件D
「各ワークが、シューティングボックスの高さより上に出ていないこと」と整合する。

**ただし「1箱に6個をどう並べるか」は未解決** (2026-09-05)。ワークはCAD実測で
直径71mmなので、内寸138mmに2列並べるには142mm要り、**内寸を均等に2分割
(ピッチ69mm)すると缶同士が2mm干渉し、壁にも1mm食い込む**。一方、
2列を壁際に寄せてY方向に半ピッチずらす**千鳥配置(3+3)なら6個入る**
(列間67mm・行ピッチ71mm以上 → 必要長177.5mm ≤ 使える184mm、余裕6.5mm)。
CADのアセンブリ名 `234_C9_Shooting_Box_4x3(最適解)` の「4x3」が「4箱×3個」を
指す可能性も残る (その場合は1箱3個)。ルールブックのボーナス条件Bが
「ワークが計6個ちょうど入っていること」なので6個説が有力だが、
**実物で並べ方を確認してから確定すること。**

### 箱の配置 (**選手が決めてよい。ルールで固定された値ではない**)

ルールブックは**「シューティングボックスの位置は選手が自由に調整することができます。
ただし、シューティングボックスがシューティングエリアの天板に触れていなければなりません」**
としている。したがって以下はCADが示す配置 (アセンブリ名
`234_C9_Shooting_Box_4x3(最適解)`) であって、規則上の固定座標ではない。
**本番で並べ方を変えたら、この表と `sharmech/params/robot_geometry.yaml` の `shooting_box` (箱の中心 `center_x/y_red|blue`・隙間 `slot_gap_x/y_m`) を変えること** (手順は `parameter_tuning.md`)。

## 赤/青の関係 (2026-08-30 確定、2026-09-12 訂正)

**青フィールドは赤フィールドを中央線で線対称にしたもの (ユーザー確認済み)。**

`field` 座標系は**ロボット自身のベース座標系**で、赤・青どちらのロボットも +X が
「自分の設置エリアから自分の作業エリアへ向かう方向」になるのは同じ。ただし**線対称**
なので、フィールド中央を向いて立つと赤で左 (+Y) にあったものは青では右 (−Y) に来る。
つまり **X は赤・青共通、Y は符号反転**:

| | 赤 | 青 |
|---|---|---|
| シューティングボックス中心 Y | +0.5255 | **−0.5255** |
| 初期位置 θ (時計回り正) | +135° | **−135°** |
| WebXR の指定箱 | 左 (+Y) | 右 (−Y) |

作業領域は Y が ±0.675 で対称なので共通。ワーク初期配置 (`work_placement`) は
赤の数値のみ持っている (読むノードが無いため未対応。青で使うときは Y を反転すること)。

**2026-09-12 までは「世界座標の鏡映と自己参照座標系が打ち消し合うので同じローカル数値」
としていたが、これはロボットを 180° 回して置く (点対称) 場合の話で、線対称では成り立たない
(誤り)。** `box_center_y_blue` を +0.5255 → −0.5255 に訂正した。

## 本番設置での原点ズレ補正

実機を設置したとき、ロボット設置エリアの設計中心と実際の設置位置がX/Y方向にずれる
可能性がある。`field_origin_offset_x_m` / `field_origin_offset_y_m` (既定 `0.0`) を
`motion_generator_node` と `game_state_manager_node` の両方に用意してあり、
現場合わせで同じ値を入れることで上記の座標全体を平行移動できる。

## 未確定/今後の課題

- **Z方向(高さ)は z 上限 (0.2098 m、2026-09-12 に実機の可動上限を実測) を除き未確定。** 今回のスケッチは上面図のみ。ワークの土台厚
  (2.3mm)は確定しているが、土台が乗る面の絶対Z、シューティングボックスの投入高さ、
  作業領域のZ下限 (`robot_geometry.yaml` で 0.0 の仮値) はすべて別途実測が必要
- **シューティングボックス内の6スロットの並べ方 (最優先)。** 箱の外形・位置はCADで
  確定したが、直径71mmの缶を内寸138×255にどう6個並べるかが未確定で、現在の
  `slot_x/y` は旧スケッチ由来のまま箱の外を指している (上記参照)
- 本番でのシューティングボックスの並べ方 (ルール上 選手が自由に調整してよいため、
  当日の配置が決まったら上記の表と config.yaml を更新すること)
- 作業エリアのX方向の真の上限(上記参照)
- ワーク初期配置の X 訂正(+40mm、2026-09-12)はユーザーの CAD 読み取りによるもので、
  シミュレータ `FieldLoader.js` の CAD 原点(x=825mm)とは 40mm 食い違う。CAD で再確認すること
- ロボット本体が赤・青で本当に同じ組み方かどうかの確認(上記「赤/青の関係」参照)
