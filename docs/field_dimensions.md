# フィールド寸法 (確定値)

**2026-08-30、ユーザーの手描きスケッチの実測から確定した、赤・青両フィールドの寸法一式。**
`catchrobo` プロジェクト全体(このリポジトリ + `catchrobo_webxr_controller` +
`catchrobo_sim_threejs`)で参照する座標の正本はここに置く。各リポジトリの
config/定数コメントはここへのリンクを持ち、値そのものは各リポジトリに複製する
(ROS2 のパラメータやブラウザ側の定数は仕組み上「1箇所を読みに行く」ができないため。
`CLAUDE.md` の「他リポジトリとの整合性確認」と同じ、意図した重複)。

**このページだけで完結するように書いてある。** 元になった手描きスケッチや、確認に
使った作業用の図(artifact)を参照しなくても、この表と図だけで同じ数値を再現できる。

## 座標系

**原点 = ロボット設置エリア(縦300×横700mm)の中心。** `field` 座標系はロボットの
ベース座標系そのもの (`CLAUDE.md`)。ROS REP-103 に沿う。

| 軸 | 向き |
|---|---|
| +X | ロボット設置エリアから作業エリア(通常/共通ワーク側)へ向かう方向。「奥」に相当 |
| +Y | 右から左。ロボット設置エリアに向かって立ち、+X方向(作業エリア側)を見たときの左手方向 |
| Z | 未確定(下記「未確定/今後の課題」) |

## ロボット設置エリア

- 縦(X方向) 300mm × 横(Y方向) 700mm、原点(0, 0)が中心
- X: `+0.150`(手前端。主エリア側)〜 `-0.150`(奥端。シューティングボックス側)
- Y: `-0.350` 〜 `+0.350`
- フィールド全体の横幅(この面の左右端): `-0.675` 〜 `+0.675`(合計1350mm)

## 赤/青の関係 (2026-08-30 確定)

**青フィールドは赤フィールドを線対称にしたもの、という前提で確定した(ユーザー確認済み)。**

`field` 座標系は**ロボット自身のベース座標系**であり、共有のグローバル座標系ではない
(`CLAUDE.md` の「field 座標系 = ロボットのベース座標系。完全に一致させる」という
決定済み方針)。世界座標での鏡映と、各ロボットが「自分自身から見た自己参照の座標系」を
持つことが打ち消し合うため、**赤・青で同じローカル数値になる**:

- 赤ロボットの +X は「自分の設置エリアから自分の作業エリアへ向かう方向」
- 青ロボットの +X も「自分の設置エリアから自分の作業エリアへ向かう方向」
- 世界座標でどちらを向いているかは、各ロボット自身の計算には現れない

したがって、このページに書かれている数値(通常/共通ワーク・シューティングボックス・
作業領域)は**赤・青共通でそのまま使える**。`sharmech_bringup/config/config.yaml` の
`game_state_manager_node.slot_x/y_red` と `slot_x/y_blue` が同じ値になっているのはこのため。

**この前提が崩れる場合:** もしロボット本体そのものの組み方(左右の関節配置、
ターンテーブルの回転方向など)まで赤・青で鏡映になっている場合は、上記の「打ち消し合い」
が成立しない。その場合は赤・青で異なる値が必要になるので、ロボット本体の組み方が
両チームで同じかどうかを確認すること。

## 本番設置での原点ズレ補正

実機を設置したとき、ロボット設置エリアの設計中心と実際の設置位置がX/Y方向にずれる
可能性がある。`field_origin_offset_x_m` / `field_origin_offset_y_m` (既定 `0.0`) を
`motion_generator_node` と `game_state_manager_node` の両方に用意してあり、
現場合わせで同じ値を入れることで上記の座標全体を平行移動できる。

- ロボット本体が赤・青で本当に同じ組み方かどうかの確認(上記「赤/青の関係」参照)
